## Follow-up: IsDot contract verified (2026-11-07)

Inspected `url/url_canon_internal.h`: `IsDot(spec)` returns 3 only if
`spec.size() >= 3` and the input begins with `%2e` or `%2E`.
`DoPartialPathInternal` invokes `IsDot(path_value.substr(i))` while
`i < path_value.size()`, so the view is non-empty. Both `path_value[i + 2]`
reads occur under `dotlen == 3`. The two index-offset alerts therefore
have a justified **likely false positive** resolution for the reviewed
source, rather than being potential out-of-bounds findings.

Added `security-lab/tests/is_dot_contract.cc` and GitHub Actions ASan/UBSan
execution for short percent escapes. This harness **reproduces only the helper
logic**, not the complete Chromium function; success does not prove Chrome
secure. The scanner now records this resolution only when it sees both the
`IsDot` contract and call-site guards.
