# Lexer: Unicode identifiers, string escapes, RegExp literal tokens (gap 3)

Survey (test262 full profile, t262-full5, `survey_syntax.py` re-runs every syntax-unsupported case
with `JS_CHECK_SYNTAX_CONTEXT=1`, which prints the offending character and line):

| group | cases | cause |
|---|---|---|
| "newline in string" | 1488 | `/'/g` inside temporalHelpers.js: `/` lexed as division, the `'` opened a string |
| "unsupported character" in a regexp | ~890 | regexp literal bodies (`\d`, `\p{..}`) |
| "unsupported character" `#` / `\` | ~1400 | `#℘`, `#\u{6F}`, `set`: non-ASCII and escaped identifiers |
| string escapes | ~100 | `\u{..}`, surrogate pairs, identity escapes, line continuations |
| "token limit" / "source limit" | 34 | 8192-token / 64 KiB caps (Unicode identifier tables) |

So "line continuations" was a misreading: the 1488 cases are a regexp literal in a harness file.

## Design
- `identifiers.rs`: ID_Start/ID_Continue from `unicode_id.rs`, generated by `gen_unicode_id.py`
  from Unicode 17.0 DerivedCoreProperties.txt (binary search over ranges; ASCII inline).
  IdentifierName accepts `\uXXXX` / `\u{..}`; each cooked code point must itself be ID_Start/ID_Continue.
  Private names use the same routine.
- An escaped identifier spelling a reserved word or a contextual keyword lexes as
  `Token::EscapedName`: valid as a property key or (if not reserved) as an identifier reference/binding,
  never as a keyword (`set x() {}` is a field named `set`, not a setter). Reserved → SyntaxError.
- Strings: the raw body is cooked by the template cooker (`template_lex::cook`), so strings and
  templates share one escape implementation: `\u{..}`, surrogate pairs combine, identity escapes,
  line continuations (LF, CR, CRLF, LS, PS). Strict mode: legacy octal and `\8` `\9` are SyntaxErrors.
  Lone surrogates stay unsupported (needs UTF-16 string storage).
- RegExp literals: `/` starts a RegularExpressionLiteral when the previous token cannot end an
  expression (start, punctuators other than `)` `]`, operators other than postfix `++`/`--`,
  `${`, and keywords like `return`/`typeof`/`in`). Body: escapes, classes (`/` inside `[...]`),
  no line terminators; flags `dgimsuvy`, no duplicates, not `u`+`v`.
  `Expr::RegExp` evaluates to `Unsupported("RegExp literal")` until the RegExp engine exists:
  code that only *contains* a regexp in an uncalled function now parses and runs.
- Source cap 8 MiB, token cap 1 Mi (were 64 KiB / 8192).
