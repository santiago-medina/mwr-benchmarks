# mozjs facade (roadmap C, option A)

`gc-lab/mozjs-facade/` is a crate named `mozjs`, version 0.26.4, with the API
Servo imports from the real mozjs. Servo's workspace dependency
`js = { package = "mozjs", version = "=0.26.4", ... }` (servo `Cargo.toml:143`)
is pointed at it, and the script crates compile against this engine instead of
SpiderMonkey. The decision and the literature check are in SERVO_BINDINGS.md.
This note covers how the crate is built and how C0 is measured.

## Layers

| Layer | Path | Origin |
|---|---|---|
| Raw bindings (`jsapi`, glue) | `src/sys/generated/{jsapi,gluebindings}.rs` | Generated by `tools/gen_sys.py` from the bindgen output shipped in mozjs_sys 153.3.0-1 (`libmozjs-x86_64-unknown-linux-gnu.tar.gz`, servo/mozjs release `mozjs-sys-v153.3.0-1`) |
| mozjs_sys Rust modules | `src/sys/{jsgc,jsid,jsimpls,jsval,trace,glue}.rs` | Copied from mozjs_sys 153.3.0-1, with `crate::` rewritten to `crate::sys::` |
| mozjs Rust layer | `src/{rust,gc,conversions,typedarray,...}.rs` | Copied from mozjs 0.26.4, with `mozjs_sys::` rewritten to `crate::sys::` |
| Engine | `gc_lab` (re-exported as `mozjs::engine`) | This repository, `#![forbid(unsafe_code)]` |

All copied and generated files keep their MPL-2.0 headers. The crate is
MPL-2.0. It has no dependencies besides gc-lab. The upstream uses of libc, log,
num_traits and encoding_rs were replaced with `core::ffi`, local `debug!` and
`log_warn!` macros, a local `PrimInt` trait and a local Latin-1 to UTF-8
loop.

### What gen_sys.py does

- It keeps every type definition verbatim: structs, unions, enums, bitfield
  units and constants. Field offsets therefore match SpiderMonkey's. bindgen's
  compile-time layout asserts come along (925 `["Size of X"]` asserts, plus
  alignment and field-offset asserts), so a layout mismatch is a compile
  error.
  This covers JSClass (48), JSPropertySpec (48), JSFunctionSpec (40),
  JSJitInfo (16), `JS::Value` (8) and every other struct Servo dereferences.
  These asserts are the "static layout asserts" the literature check asked
  for.
- Each `extern "C"` declaration (1,097 in jsapi, 118 in glue) becomes a Rust
  `pub unsafe extern "C" fn` with the same signature. Its body calls
  `sys::unimplemented_entry(name)`, which panics. A panic cannot unwind out of
  an `extern "C"` function, so the process aborts with the entry point's name.
  This is deliberate in C0: a stub must never return a made-up value.
- Each extern static (115 + 3) becomes a zeroed static that keeps bindgen's
  mutability. `extern const` statics stay immutable, because Servo borrows
  `&ProxyClassOps` and the other proxy hooks inside a `static JSClass`
  (`tests/servo_statics.rs`). The exceptions are the const statics whose types
  hold raw pointers: they are not `Sync`, so they stay `static mut`
  (`tools/nonsync_statics.txt`, 27 names).
  Four statics get real values (`STATIC_INIT` in gen_sys.py):
  `JS::{Null,Undefined,True,False}HandleValue` point at fixed `JSVal` cells
  in `sys/jsval.rs`, as SpiderMonkey's point at `static const Value`s.
  Zeroed, they made `Handle::from_raw(UndefinedHandleValue)` panic in
  Servo's `window_named_properties::create` (probe at 76859c3).
- It drops the C variadic tails (`...`), because Rust cannot define variadic
  functions. The affected functions are JS_ReportError{ASCII,Latin1,UTF8},
  JS_ReportErrorNumber{ASCII,Latin1,UTF8,UC}, Warn{ASCII,Latin1,UTF8} and
  JS_ExpandErrorArgumentsASCII. Servo calls none of them. The only internal
  caller, mozjs's `error::throw_js_error`, now uses
  `JS_ReportErrorNumberUTF8Array`.
- `::libc::FILE` becomes `c_void`.

Regenerate with `python3 tools/gen_sys.py <mozjs-sys download dir>
src/sys/generated`. `SetGCZeal` exists only in SpiderMonkey debug builds, so
the release bindgen output lacks it. Servo imports it under `debugmozjs`, so
`src/sys/mod.rs` adds it by hand.

## unsafe

The facade is the boundary layer, not the engine. The mozjs API is
raw-pointer `unsafe extern "C"` by construction, and the facade keeps it so
Servo compiles unchanged. Inventory at C0 (occurrences of the `unsafe`
keyword):

- generated jsapi: 1,643; generated glue: 167. These are the stub signatures,
  bindgen's bitfield helpers and the `unsafe impl Sync`/`Send` lines.
- copied mozjs and mozjs_sys Rust: 432.
- gc-lab: 0 (`forbid(unsafe_code)`).

The rule for C1 onwards: each stub body becomes a thin conversion from raw
pointers to engine ids, then a call into the safe `gc_lab::script::embed` API.
No engine logic lives in the facade. Code that touches raw memory (Rooted
stacks, Heap barriers, JSString chars) stays in the sys modules copied from
upstream and gets a `// SAFETY:` comment when it changes.

## Implemented entry points

`tools/implemented.txt` lists the extern entry points that have a real body.
For each listed name `tools/gen_sys.py` emits a forwarder to
`crate::sys::imp::NAME(args)` instead of the `unimplemented_entry` stub; the
generator fails if a listed name is missing from the bindings or appears
twice. The bodies live in `src/sys/imp/*.rs`, one file per cluster.

Context cluster (`src/sys/imp/context.rs`, 40 entry points: everything
`JSEngine::init`, `Runtime::new` and Servo's `Runtime::new_with_parent` call
before the first global). `JS_NewContext` boxes a `#[repr(C)] Context` whose
first field is `JS::RootingContext` (zeroed: empty rooted lists), so
`Rooted` linking and the `cx as *mut RootingContext` casts in `rust.rs` and
`jsimpls.rs` work unchanged; `JSRuntime*` is the same address. Callbacks,
hooks, GC parameters, stack quotas and the job queue traps are stored in a
`RefCell<State>` on the context; they take effect once the engine drives
them (GC, promise jobs, modules). `tests/context.rs` covers init, runtime
creation, a GC parameter round trip and stack rooting.

Proxy and principals cluster (`src/sys/imp/proxy.rs`, 11 entry points: what
`script::init` calls before any runtime). A handler pointer points to a
leaked `Handler` holding a copy of the `ProxyTraps`, the `extra` pointer
(the interface's `DOMClass`) and its kind; `GetProxyHandlerFamily` is the
address of a static. Principals follow jsglue's `RustJSPrincipals` (a
`JSPrincipals` prefix, then callbacks and private data), and
`JS_DropPrincipals` calls the runtime's destroy callback at zero.

Globals cluster (`src/sys/imp/objects.rs` plus five hooks in `context.rs`,
25 entry points: Servo's `create_global_object`, `select_compartment`,
`JSAutoRealm` and module hook setup). `JS_NewGlobalObject`,
`JS_FireOnNewGlobalObject`, `EnterRealm`/`LeaveRealm`, `CurrentGlobalOrNull`,
`GetRealmGlobalOrNull`, `GetObjectRealmOrNull`, `GetNonCCWObjectGlobal`,
`JS_IsGlobalObject`, `GetRealmPrincipals`, `JS_SetTrustedPrincipals`,
`JS_IterateCompartments`, `IsSharableCompartment`, `IsSystemCompartment`,
`JS_GetCompartmentPrivate`, `JS_NewObject`, `JS_NewObjectWithGivenProto`,
`JS_GetReservedSlot`, `JS_SetReservedSlot`, `JS_GC`, `GetModuleLoadHook`,
`GetModuleMetadataHook`, `JS_AddInterruptCallback`, `SetWindowProxyClass`,
`GetWindowProxyClass`. `tests/globals.rs` covers them, including the inline
class and realm reads and survival across `JS_GC`.

Natives, strings and interface objects cluster (`src/sys/imp/natives.rs`,
46 entry points: what `create_interface_prototype_object`,
`create_interface_object`, `create_namespace_object` and the constant and
unforgeable setup in script_bindings/interface.rs and constructor.rs call per
global). Functions: `JS_NewFunction`, `JS_GetFunctionObject`,
`RUST_FUNCTION_VALUE_TO_JITINFO`. A host function's word indexes the
context's native table (`JSNative`, `JSJitInfo*`, the function object), so
the JIT info of a function value is a table lookup. Spec lists:
`JS_DefineFunctions` (C-string or well-known-symbol names, encoded as
`SymbolCode + 1`; `JS_SELF_HOSTED_FN` names map to the Array iteration
methods Servo uses for iterable and maplike interfaces: `$ArrayValues`,
`ArrayKeys`, `ArrayEntries`, `ArrayForEach`; any other self-hosted name
fails) and `JS_DefineProperties` (native accessors become "get x" / "set x"
functions, ECMA-262 §10.2.9; string, int32 and double values; self-hosted
accessors fail). Properties: `JS_DefineProperty` and its overloads 1-7,
`JS_DefinePropertyById2/4/5`, `JS_DefineElement`, `JS_GetProperty`,
`JS_HasProperty`; `JSPROP_READONLY`, `JSPROP_ENUMERATE` and
`JSPROP_PERMANENT` map to writable, enumerable and configurable.
Prototypes: `JS_LinkConstructorAndPrototype`, `JS_GetPrototype`,
`JS_SetPrototype`, `JS_SetImmutablePrototype` (ECMA-262 §10.4.7; the engine
gained an immutable-prototype flag, and Object.prototype already behaves so).
Realm intrinsics: `GetRealm{Object,Function,Error,Iterator}Prototype`,
`JS_NewPlainObject`. Strings are interned, leaked `StringCell`s holding the
text, its UTF-16 form and its Latin-1 form when every unit fits
(`JS_AtomizeAndPinString`, `JS_NewStringCopy{N,Z,UTF8N}`,
`JS_Get{Latin1,TwoByte}StringCharsAndLength`,
`JS_DeprecatedStringHasLatin1Chars`, `JS_GetStringLength`); invalid UTF-8
returns null. Symbols are `SymbolCell`s over the engine's symbol number
(`GetWellKnownSymbol`, `RUST_SYMBOL_TO_JSID`). `AddAssociatedMemory` and
`RemoveAssociatedMemory` only count bytes; the collector does not use the
count yet. There are no cross-compartment wrappers (every compartment shares
one engine heap), so `UncheckedUnwrapObject` and `CheckedUnwrapStatic` are
identities, `IsWrapper` is false and `JS_WrapObject` / `JS_WrapValue`
succeed unchanged. There is no Debugger API: `JS_DefineDebuggerObject`
succeeds without defining `Debugger`, so Servo's devtools debugger scripts
fail where they use it. `tests/interfaces.rs` covers the cluster, including a
reentrant native getter.

Pending exceptions (`imp/context.rs`): the context holds one pending
exception value. `JS_SetPendingException`, `JS_GetPendingException`,
`JS_IsExceptionPending` and `JS_ClearPendingException` read and write it. A
JSNative that returns false with an exception pending throws that value into
the engine (`Engine::throw_value`), so script `try`/`catch` sees it; false with
nothing pending is an uncatchable error, as OOM is in SpiderMonkey. In the
other direction, an entry point whose engine call ends in a thrown completion
returns false and leaves the thrown value pending. Engine faults and
Unsupported leave nothing pending and are logged.

### GC barriers

`imp/barriers.rs`. SpiderMonkey's write barriers (`HeapObjectWriteBarriers`,
`HeapValueWriteBarriers` and the string, BigInt and script variants,
`IncrementalPreWriteBarrier`) serve its incremental marking and its
generational, moving nursery. Under the C1 keep-alive policy (cells never
freed, every cell a root) the engine needs neither, so the barriers are
no-ops, `IsIncrementalBarrierNeeded` is false and
`SetNativeObjectReservedSlotWithBarrier` is a plain reserved-slot store. When
C2 lifts the keep-alive policy, `Heap<T>` fields must become traced edges
instead: the barrier entry points are where a facade-side remembered set
would hook in, if the collector ever becomes incremental.

Standard classes: the engine defines every standard class when it creates a
global, so `JS_ResolveStandardClass` resolves nothing, `JS_MayResolveStandardClass`
is false and the enumerate hooks add nothing.

### Property access by id, descriptors and calls

`imp/props.rs`, 64 entry points: what Servo's generated bindings and DOM proxy
handlers run on every object once interfaces exist.

- Ids. An array index up to 2^31 - 1 becomes an int jsid and every other key
  an atom (`RUST_INTERNED_STRING_TO_JSID`, SpiderMonkey's AtomToId), so ids
  Servo compares by bits match the ones the engine hands back. Array indices
  follow ECMA-262 §6.1.7 (`StringIsArrayIndex`).
- Property access by id or name: get (also with a forwarded receiver), set
  (a refusal throws TypeError, ObjectOpResult::checkStrict), has, has-own,
  delete (ObjectOpResult with `JSMSG_CANT_DELETE`), define from a partial
  `JS::PropertyDescriptor` (`Engine::define_own_property`, §10.1.6) or from
  JSNative accessors, own and inherited descriptors (with the holder), freeze
  (§7.3.15) and `SetPropertyIgnoringNamedGetter`, which follows
  OrdinarySetWithOwnDescriptor (§10.1.9.2) with the caller's descriptor.
- Id vectors: a `PersistentRootedIdVector` is a facade `IdVectorCell`; it holds
  only interned atoms and symbols, so it needs no tracing. `GetPropertyKeys`
  honours `JSITER_OWNONLY`, `HIDDEN`, `SYMBOLS` and `SYMBOLSONLY` and walks the
  prototype chain without duplicates (§14.7.5.9).
- Linear strings are the interned string cells: char access, length,
  code-unit comparison (`JS_CompareStrings`), ASCII equality, concatenation,
  ToString (§7.1.17) and ToBoolean (§7.1.2).
- Calls: `Call` (§7.3.14), `JS_CallFunctionValue`, `JS_CallFunctionName`,
  `Construct` (§7.3.15; a `newTarget` other than the function throws
  TypeError, not supported yet), `IsCallable`, `JS_IsNativeFunction`,
  `GetFunctionRealm` (§7.3.24). `JS_ObjectIsFunction` is IsCallable: the
  engine has no callable non-function host objects.
- Wrappers are the identity, so `IsWindowProxy` compares the class with the
  registered window proxy class, `JS_IsDeadWrapper` is false and
  `UnwrapObjectDynamic` returns its argument. `GetCurrentRealmOrNull` reads
  the context's realm.

### Microtasks (js/public/Promise.h)

SpiderMonkey leaves the microtask queue to the embedder, and so does the
facade (`src/sys/imp/jobs.rs`). A `GenericMicroTask` is a `JS::Value`: an
object is a `JSMicroTask*` (an engine promise job), anything else is the
embedder's own task (Servo enqueues a `PrivateValue` boxing a Rust runnable).

- The engine reports each promise job through `Host::enqueue_job`
  (HostEnqueuePromiseJob, ECMA-262 §9.5.5). That is a notification only. The
  facade appends `Js(serial)` to its queue, which `EnqueueMicroTask` and
  `PrependMicroTask` also feed, so one queue holds both kinds in order.
- Dequeuing a job hands out the cell of the engine object that holds the job
  record. `RunJSMicroTask` runs that serial with `Engine::run_host_job`
  wherever it sits in the engine's queue, so the facade's queue, not the
  engine's, decides the order. After the run the cell stops being a root.
- `GetExecutionGlobalFromJSMicroTask` returns the global of the handler's
  realm (NewPromiseReactionJob and NewPromiseResolveThenableJob step 3,
  §27.2.2.1-2). If the job has no handler, it falls back to the job's
  realm and then the current realm. It never returns null for a pending
  job, because Servo skips a task whose global is null.
- Not modelled yet: incumbent globals and host-defined data
  (`MaybeGetHostDefinedDataFromJSMicroTask` returns null for both, which
  Servo reads as "no incumbent"), the promise behind a job, the user-input
  flag (always `DontCare`), and the debugger queue (always empty).
  `JobQueueIsEmpty` and `JobQueueMayNotBeEmpty` are hints, and the engine
  always queues. `GetJobQueue` returns the pointer `SetJobQueue` stored.
- Jobs cancelled after an engine fault are pruned before any `Has*`, count,
  peek or dequeue call, so Servo never dequeues a job that cannot run.

Test: `tests/microtasks.rs` (an embedder task prepended, a promise job, and
an embedder task appended, drained in order; a collection runs between the
dequeue and the run).

### Classic scripts and error reports

`imp/scripts.rs`, 14 entry points: what Servo's `evaluate_js_on_global`
(components/script/dom/globalscope.rs) and `ErrorInfo::from_native_error`
(dom/bindings/error.rs) call.

- `NewCompileOptions` boxes a zeroed `ReadOnlyCompileOptions` (SpiderMonkey's
  defaults) with an owned filename. Servo writes the remaining fields inline.
- A `JSScript*` is a leaked `ScriptCell` that holds the source text, the
  filename, the line and the private value. `Compile`/`Compile1` run the
  parser for early errors (ParseScript, ECMA-262 §16.1.6), and
  `JS_ExecuteScript` runs ScriptEvaluation on the same text, so a script is
  parsed twice until the engine has a compiled-script object. A parse error
  leaves a pending SyntaxError. Unimplemented syntax stays uncatchable
  Unsupported, never a SyntaxError. Malformed UTF-8 is a SyntaxError. UTF-16
  source with a lone surrogate is refused as Unsupported: the engine takes
  `str` source, and the facade does not change the text.
- `SetScriptPrivate` calls the runtime's reference hooks
  (`SetScriptPrivateReferenceHooks`) on the new and the old value, as
  ScriptSourceObject::setPrivate does.
- `Hide`/`UnhideScriptedCaller` only count nesting. `GetScriptedCallerGlobal`
  and `DescribeScriptedCaller`, which read that count, are not implemented
  yet.
- `JS_ErrorFromException` returns false for objects without [[ErrorData]].
  For errors, it builds one cached report per object: the message is the
  own `message` property with no "Name: " prefix, as in
  ErrorObject::getOrCreateErrorReport, and `exnType` comes from the error
  class. The engine does not record where an error was created, so the
  filename is empty, the line is 0 and the column is 1.
- There is no `Debugger`. `JS_DefineDebuggerObject` is a no-op, so Servo's
  debugger.js (`new Debugger`) throws a ReferenceError at startup. That
  exercises the error-report path; nothing pretends a Debugger exists.

Unforgeable holders (`imp/props.rs`): `JS_NewObjectWithoutMetadata` is
`JS_NewObjectWithGivenProto`, because the engine attaches no allocation
metadata. `JS_InitializePropertiesFromCompatibleNativeObject` defines each
own property of the holder on the fresh object with its full descriptor, in
[[OwnPropertyKeys]] order.

The glue's `PendingExceptionStackInfo`, which Servo's
`error_info_from_pending_exception` calls to report an uncaught exception,
steals the pending exception and describes it as SpiderMonkey's
`JS::ErrorReportBuilder::init` does: an [[ErrorData]] object gives the
`JS_ErrorFromException` report (bare message, empty filename, line 0,
column 1); any other value gives "uncaught exception: " + ToString(value)
(SymbolDescriptiveString for a Symbol, "unknown (can't convert to string)"
when ToString throws) with no filename, because the engine records no saved
frame for it.

Test: `tests/scripts.rs`.

Reporting the error then calls `GlobalScope::from_current_realm`, which reads
`CurrentRealm::global()`, i.e. `JS::CurrentGlobal`. SpiderMonkey returns the
address of the entered realm's `global_` field. The facade returns the

`js::AddRawValueRoot`/`RemoveRawValueRoot` (Servo's `PermanentRoot`) keep a

### GC policy

The facade creates its engine with the engine's default policy,
`GcPolicy::Stress`, which collects at every allocation safepoint. Under
Stress, every facade entry point that holds a fresh, unrooted object across
another allocation fails at once with `Memory(InvalidHandle)`. At 7ec6a3d,
`define_native_accessor` built the getter and then the setter, and the
collection during the setter's allocation freed the getter. The probe stopped in `define_guarded_properties`
(AbortSignal's `onabort`, the first accessor with both a getter and a setter).
Its run.log named `HasAnyMicroTasks`, because that stub ran during the unwind
(`Runtime::drop`). The getter is now rooted across the setter's allocation,
and `tests/interfaces.rs` covers a getter+setter pair.

Stress stays the policy while C1 brings up startup paths, because it turns
rooting bugs into immediate, reproducible failures. It is far too slow for
pages: switch the facade to `GcPolicy::Threshold` before C2 or any
performance measurement (see "Next (C1)").

## Engine ownership, reentrancy and object pointers

Global creation (`JS_NewGlobalObject`, script_bindings/interface.rs
`create_global_object`) is the first entry point that needs engine objects.
Decisions, following SERVO_BINDINGS.md option A:

- **One engine per context.** The facade `Context` owns a
  `gc_lab::script::Engine<'static>` in a slot (`RefCell<Option<Engine>>`).
  Each `JS_NewGlobalObject` is `Engine::create_global_realm` (a new realm,
  REALMS.md) plus `attach_host` on the realm's global with Servo's `JSClass`
  address as the class word and `JSCLASS_RESERVED_SLOTS(flags)` slots.
  `JSAutoRealm` / `JS::EnterRealm` map to `enter_realm_id`.
- **Reentrancy without `unsafe`.** While Servo code runs, the engine is in
  the context slot, and facade entry points borrow it there. When the facade
  calls into the engine (a call, an evaluation), it takes the engine out of
  the slot. When the engine calls a host function (`Host::call(&mut Engine)`),
  the facade swaps that engine with a spare one (`mem::replace`), puts the
  real one back in the slot for the duration of the JSNative, then swaps it
  back. `Engine::detach` rebinds the engine's lifetime to `'static` for the
  slot; it refuses (and the call fails) if a DOM adapter borrows into the
  engine, so a parked engine never holds a borrow. Spares are hostless
  engines kept in a pool, one per nesting level. Each host call costs two moves of the `Engine` struct; the overhead
  micro-benchmark (Next, item 5) measures it. The alternative, a thread-local
  raw `*mut Engine` set during host calls, would add a fourth `unsafe` site
  that the design note does not allow.
- **Object pointers are cell addresses.** Servo reads objects inline:
  `mozjs::rust::get_object_class`, `get_object_realm` and `get_context_realm`
  dereference `JSObject*` as `shadow::Object { shape }` -> `shadow::Shape
  { base }` -> `shadow::BaseShape { clasp, realm }`, and read
  `RootingContext.realm_`. Integer tokens (the first design: `(slot + 1) * 16`
  over a table) would crash on the first such read. So a `JSObject*` is the
  address of a leaked `#[repr(C)] ObjectCell` whose first field is a
  `shadow::Object`, pointing to an interned `ShapeCell` (one per class and
  realm). The cell holds the engine `ObjectId`; `Heap.cells` maps
  `ObjectId -> cell` so the same object always yields the same pointer.
- **C1 keep-alive policy.** Cells are never freed and every object that has a
  cell is reported as a root (`Host::trace_roots`) until tracing (E4) tells
  the facade which objects Servo still holds. This leaks by design in C1 and
  is listed with the guards to lift before C2.
- **Reserved slots are facade-side.** Slots are stored as raw `JSVal` bits
  per object, so `PrivateValue` doubles and int32 tags round-trip exactly;
  `Host::trace` reports the object-valued ones to the engine.
- **Compartments** are leaked `CompartmentCell`s (system if the global's
  principals are the trusted principals). `ExistingCompartment` reuses one;
  all compartments share the context's engine.
- **Guards.** `create_global_realm` inherits the 64-realm cap of `new_realm`,
  a test-harness guard. It is listed with the call depth and step limits to
  lift before C2.
