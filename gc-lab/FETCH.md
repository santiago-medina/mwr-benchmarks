# Native fetch boundary

The interpreter exposes fetch(url) and response.status/ok/url/bodyUsed/text(). Header and body delivery are separate host invocations. Pending operations are ordinary traced records containing the existing intrinsic Promise capability and, for body reads, their Response. External roots retain these records until completion or cancellation. No expression is replayed after suspension.

DomAdapter opts into native networking and receives monotonically increasing operation IDs. Native callbacks must arrive between VM invocations with the same registry reattached. Wrong-kind completions are rejected without consuming the pending operation; retired and duplicate IDs return false. An ignored successful header completion leaves resource disposal to the host that owns its native response. Cancellation while suspended queues native aborts until the host reattaches. Realm release drops VM operation roots; native document unload retires the session before aborting transport, so no rejection or queued job can resume the unloaded VM. Runtime teardown also drops the response registry.

Responses use one shared lazy prototype, ordinary descriptors, and a small private slot. A pending text operation keeps its Response alive. Dead Response wrappers release native resources at collection. HTTP errors fulfill fetch; transport, origin and policy errors reject with TypeError. A non-null body can be consumed once. Null bodies resolve to an empty string without a native body read, remain unused and can be read repeatedly. The adapter normalizes Servo placeholder streams for null-body HTTP statuses. Network completion resolves Promises but never drains VM jobs inline. Terminal resource/runtime errors cancel pending work.

The Servo adapter invokes the same native Fetch algorithm as Window::Fetch, with the real document, default RequestInit and a private AbortController. A cancellation anchor then detaches the canceled listener context and global root, and removes its aborted fetch record, so a stalled server cannot retain a retired document through native networking. Ordinary Window::Fetch keeps its existing behavior. Native PromiseNativeHandler callbacks carry pipeline/operation IDs only. Response::Text performs native decoding. Servo therefore owns URL resolution, redirects, credentials, origin/CORS/CSP checks and transport cancellation. This is not a second HTTP client. No interpreter source or user function is sent to SpiderMonkey. Servo still owns DOM reflectors and its native Promise/Fetch infrastructure.

Limits: URL GET/default options only; non-undefined RequestInit is explicitly unsupported. No Request or Response constructors, exposed AbortSignal, headers API, JSON conversion, streaming, blob, arrayBuffer or Response.clone. This boundary is not full WebIDL/Fetch conformance.

Validation: ten fake-host contracts exercise separate deferred headers/body delivery under both GC arena models, error/rejection behavior, consumption and brands, null bodies, navigation-style realm release, stale IDs, suspended cancellation and URL conversion failures. The native run_fetch.py runner serves local HTTP fixtures, holds response bytes until it observes header completion, and holds document load until native DOM observation confirms the expected outcome. Its scenarios cover success, 404, 204, connection failure, cross-origin denial, connect-src denial and navigation while awaiting body bytes. The navigation probe requires the old session and document to be collected and exercises the completion dispatcher with a retired pipeline ID.

Native evidence is pending until the cached Actions build and all scenarios pass. See workflow artifacts; do not infer native success from core contracts.
